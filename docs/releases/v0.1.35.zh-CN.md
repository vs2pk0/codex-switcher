# Codex Switcher v0.1.35

本版本新增会话「一键修复」，为 OpenCodex 与本地 API 服务补齐 Codex 实例接入流程和 OAuth 登录态绑定，并修复接入后 Codex 不显示账号的问题。

## 主要更新

### 会话一键修复

- 会话页新增「一键修复」：一次完成切号会话修复与当前实例全部会话的完整历史恢复，修复期间 Codex 保持关闭，完成后询问是否重启。
- 修复过程改为后台线程执行，并以应用内全屏遮罩展示步骤进度，避免系统忙碌光标，同时阻止误操作其他页面。
- 原「修复可见性」入口收起，由一键修复统一覆盖。

### OpenCodex 与 API 服务接入 Codex 实例

- OpenCodex「同步配置」改为：关闭实例 → 恢复基础配置 → 注入路由 → 绑定 OAuth 登录态 → 一键修复 → 重新打开实例，全程遮罩显示进度。
- API 服务页新增「同步配置」「恢复配置」：把所选实例的 `model_provider` 指向本地 CLIProxyAPI（自动维护账号总览中的「本地 API 服务」账号），恢复时切回基础配置并同步会话 provider。
- 多开实例卡片与实例选择弹窗显示「API 服务」接入标识；启动实例时若依赖的 OpenCodex / API 服务未运行，会先拉起服务再打开 Codex。
- 开启或停止 API 服务后自动刷新实例列表。

### OAuth 登录态绑定

- 同步配置时自动绑定 OAuth 账号：优先实例当前账号，其次账号列表中第一个可用账号，并完成 Token 续期。
- OpenCodex 页与 API 服务页新增「绑定 OAuth」，可更换或取消绑定；实例运行中会自动重启使其生效。
- 修复接入代理后 Codex 只显示 Provider 名称、不显示账号的问题：API 服务采用 `requires_openai_auth = true` + `X-Api-Key` 网关鉴权头写入 Provider，OpenCodex 注入的 Provider 在绑定后切换为 ChatGPT 登录模式，启动实例前自动补正。
- 「绑定 OAuth」的当前账号仅在 auth.json 登录态确实属于该账号时显示。

### 账号切换

- 切换账号时，若目标实例已接入 API 服务、OpenCodex 或第三方 API Key Provider，先重置 `config.toml` 再写入账号数据，避免旧路由残留。
- 修复 API Key 账号绑定 OAuth 时未按多开实例作用域判断当前账号的问题。

## 验证情况

- 前端类型检查与单元测试通过（含新增的实例接入、切换前重置、自动绑定形状测试）。
- Rust 单元测试通过（含 OAuth 登录态写入、本地网关 Provider 写法、OpenCodex 登录模式切换、候选账号顺序等测试），clippy 与 rustfmt 检查通过。

## 安装包

GitHub Actions 会自动构建并发布 Windows x64 和 macOS arm64 安装包。Codex 桌面多开当前仅支持 macOS。macOS 安装包使用 ad-hoc 签名，未进行 Apple 公证；首次启动时可能需要在系统设置中允许打开应用。
