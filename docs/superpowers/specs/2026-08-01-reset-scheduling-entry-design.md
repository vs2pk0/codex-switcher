# 重置预约入口与列表分离设计

## 背景

当前“选择重置次数”弹窗把立即重置、预约时间、倒计时和取消预约集中在同一个区域，信息过重。项目已经有独立的“重置记录”页面，可承载活动预约和执行日志。

## 目标

- 重置次数弹窗只负责展示可用次数明细并发起立即重置或预约操作。
- 创建预约时使用独立、轻量的时间选择弹窗。
- 已有预约时在重置次数弹窗显示清晰的“已预约”标识。
- 点击“已预约”直接进入“重置记录”页面。
- 预约时间、实时倒计时、取消操作和重置日志只在“重置记录”页面展示。

## 交互流程

### 创建预约

1. 用户从账号卡片打开“重置次数明细”弹窗，确认账号存在可用重置次数。
2. 弹窗底部同时显示“取消”“立即重置”“预约重置”三个操作。
3. 点击“预约重置”打开独立的预约时间弹窗；原重置次数弹窗继续保留在背景中。
4. 用户选择晚于当前时间的本地日期时间并保存。
5. 创建成功后关闭两个弹窗，刷新本地预约状态，并提示“预约重置已保存”。

### 查看已有预约

1. 账号存在活动预约时，“选择重置次数”弹窗不显示日期、倒计时或取消预约区域。
2. 预约按钮改为“已预约”，保持可点击；立即重置按钮保持禁用，防止重复消耗。
3. 点击“已预约”关闭重置次数弹窗并切换到 `resets` 视图。
4. “重置记录”页面展示预约账号、预约时间、状态、实时倒计时、取消入口和历史日志。

## 组件边界

- `ResetCreditModal.vue`
  - 删除立即/预约模式切换和内嵌预约详情。
  - 以只读方式展示重置次数明细，保留立即重置按钮。
  - 新增统一的预约入口事件：无活动预约时请求创建预约，有活动预约时请求打开预约列表。
- 新增轻量预约时间弹窗组件
  - 只接收可见状态、账号信息和保存状态。
  - 负责日期时间输入及基础有效性判断。
  - 通过事件把时间戳交给 `App.vue`，不直接读写持久化状态。
- `App.vue`
  - 管理预约时间弹窗状态与当前选中的重置次数。
  - 复用已有 `handleScheduleReset` 创建逻辑。
  - 处理“查看预约”事件：关闭相关弹窗并调用 `switchView("resets")`。
- `ResetPanel.vue`
  - 继续作为预约和日志的唯一详情页，不改变现有持久化与调度逻辑。

## 状态与错误处理

- 没有可用重置次数时，预约按钮禁用。
- 已有活动预约时，预约按钮变为“已预约”入口，不允许再次创建。
- 预约时间为空、格式无效或不晚于当前时间时阻止保存并给出提示。
- 保存期间禁用重复提交；失败时保留时间弹窗及用户输入，成功后才关闭。
- 调度执行、应用关闭期间错过任务、日志上限等行为保持现有实现不变。

## 验收标准

1. “重置次数明细”弹窗不再出现具体次数选择、预约模式切换、日期输入、倒计时和取消预约。
2. 未预约账号可通过独立“预约重置”按钮打开时间选择弹窗并成功创建预约。
3. 已预约账号显示可点击的“已预约”标识，点击后进入“重置记录”页面。
4. “重置记录”页面继续正确展示预约时间、每秒倒计时、取消预约和日志。
5. 已有活动预约时不能立即重置或重复预约。
6. 快速重复点击不会创建重复预约或产生相互矛盾的成功、失败提示。
7. 前端类型检查、构建和 Rust 预约状态测试通过。

## 非目标

- 不改变“仅应用运行期间执行”的调度约束。
- 不增加系统后台任务、通知或应用关闭后的补偿执行。
- 不修改现有 Rust 数据模型、持久化格式或 Windows/macOS 图标资源。
